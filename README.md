# AOSC Anicca Telegram Bot

Cloudflare Worker：定时读取 Anicca 的上游更新列表，推送频道通知和个人订阅通知。

## 本地验证

安装锁文件中的开发依赖后运行：

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm check
```

测试使用 Node 内置测试运行器和项目已有的 TypeScript 编译器。Telegram、上游请求和 KV 均为隔离模拟，不发送真实消息，也不访问 Cloudflare。测试覆盖同键写入限流、历史版本去重、分批处理、订阅队列、旧数据迁移、配置缓存及保存失败。

## 通知状态与 KV 用量

- 已发送记录以包名、目标版本和路径识别。上游暂时缺项或返回空列表不会删除历史记录；新的目标版本仍会通知。
- 去重记录、待发私信、最后保存的 hash 和时间存放在一个 `notification_state` 键中。每轮先在内存中处理，再统一保存一次；短暂保存失败只重试保存，不重发本轮消息。
- 无新更新且无待发私信时，只读一次通知状态，不写入、删除或列举 KV，也不发送空闲提示。仍会抓取上游，避免遗漏相同文件中尚未处理完的批次。
- 正常有工作的一轮使用 2 次 PUT（处理锁、通知状态）和 1 次 DELETE（释放锁）；失败重试和错误记录会增加调用量。订阅用户每轮扫描一次，配置每次调用读取一次。批量订阅也只保存一次用户记录。
- `lastTs` 表示最近一次持久保存通知状态的时间，不是每次定时检查的心跳时间。`/` 和 `/debug` 读取同一状态。

首次处理时自动读取旧的 `last_sigs`、`subs_queue`、`last_hash` 和 `last_ts`，兼容旧签名的 JSON 字符串数组、对象数组和逐行文本格式。迁移与本轮结果合并保存，旧键保留不修改；后续只读取新状态。已有订阅和配置键保持原样。不要通过删除新状态键来重置机器人，否则会再次读取过时的旧记录。

回退旧代码前，需要将新状态中的 `signatures`、`queue`、`lastHash`、`lastTs` 分别同步回上述旧键，否则旧代码会从迁移前的位置继续处理。不要让新旧版本同时处理通知。

历史签名目前不自动过期，以免旧版本重现时再次通知；存储会随实际通知的版本数增长。此方案仍使用原有 KV 锁，没有增加存储服务或依赖。

Telegram 发送与 KV 保存不是一个事务：若进程在发送后被终止，或保存持续失败，下一次执行仍可能重发未持久记录的消息。保存失败会记录并通知管理员，同步 `/trigger` 返回失败；这里不承诺跨服务的严格“只发送一次”。

本地测试和检查不会部署。部署配置使用仓库未跟踪的 `wrangler.toml`；`wrangler.toml.default` 仅为配置模板。
